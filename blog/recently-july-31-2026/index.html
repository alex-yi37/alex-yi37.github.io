It's been a little over a month since we arrived in Tokyo (June 22nd, today it's July 31st) and it's been quite the experience. We started language school on July 8th and it's been pleasant. The instruction itself is better than I was expecting, and while my class is kind of big it doesn't feel too too big. There's a good mix of speaking practice, grammar and vocab practice, and writing kanji. I will say, I'm not really a fan of writing kanji by hand just because it feels like something that's only directly useful when filling out forms at a government office or doctor's office, but it is kind of enjoyable at times and apparently helps with memory retention. Ultimately, I'll probably forget how to write the majority of the kanji that I practice writing, but would like to think it'll help me recall them a bit better when reading. As for my classmates, it feels like there's a bit of variation (obviously) - some people seem to be able to speak pretty well already, while others struggle a bit, and some people can read and comprehend stuff quickly while others take a little more time. Overall, I'm pretty satisfied with the instruction so far. My one complaint would be that the classroom is arranged in such a way that if you're sitting in the front row at one of the corner desks, you can't really see the whiteboard. I happen to be sitting in one of those seats, but it's not the end of the world.

Events

I went to my first TokyoDev event on the 21st and took the opportunity to volunteer for it. I was a little nervous going into it since I've never really helped run a tech event before, but it was actually fine. There wasn't anything too complex. I had to help guide people entering the venue, which was actually a bit more involved than I expected because attendees needed to use an app to get inside, and said app didn't always cooperate, and then just put some chairs out and clean up. It feels like I haven't really been part of a tech community for a while, especially not an in-person one, so being able to talk to people about development and such is nice, even if I don't always have much to contribute to the conversation. I got the chance to talk to someone for a bit, but we actually didn't talk about development or anything for very long, just chatted about his experience being in Japan and learning the language. I got some good tips from him, a big one being to try to practice sounding more natural when speaking by recording yourself saying a sentence that someone else said, then listening to it to check your rhythm, pronunciation, etc. I have yet to try doing this...but I'd like to work it into my routine somehow. Just need to find a source that I could get sentences from, perhaps I could start with the shadowing practice in my Minna no Nihongo book.

Projects

An idea I had for a little web app was to read a transit card's NFC chip to obtain data such as fare price, entrance and exit stations, etc so that I can sort of track my spending on train fare. This was primarily motivated by the fact that visibility into that information isn't readily available. You have to either go to a kiosk at a station to then print out that a receipt that shows the info, or use a mobile app to read the card. Going to a station every time you want that data is pretty inconvenient, and I'm opposed to downloading apps unless I really need to. I actually did download an app to see what the process was like, and I had some more qualms with it. For one (and I believe this is a limitation of the transit card itself, not the app) you can only see the last twenty trips when scanning. Worse than that, you have the option to download a csv of your ride history on the app to presumably use yourself, but it's a paid option. I'd have preferred if the option wasn't even given to me and instead just shown in a list of premium features somewhere else.

In any case, that was my motivation for wanting to make the app. To preface the rest of this, it seems like my idea is not viable due the fact that I wanted to use the Web NFC API to read the data. It seems that the NFC cards used for transit in Tokyo use a proprietary format that isn't supported by the API unfortunately according to this page. Before knowing this, I attempted writing a simple JS module loaded on an html page to test out the Web NFC API. I first had to figure out how to access the app from my Android phone in development as the Web NFC API is only available on Chrome Android versions 89 and onward, and only over https. I was using the Live Server VSCode extension to serve the page over localhost, and then accessing said page using my phone over my local network by writing my laptop's local IP address in place of localhost in the url. The extension also offers some config options where you can provide the absolute path to https (TLS?) cert(s) on your file system to serve the page over a secure connection. To generate the TLS cert I tried using mkcert and used the generated certs in my Live Server config. I was able to access the page on my phone, but not over https unfortunately. From my understanding, I would only be able to access the page over https from my laptop using this setup, but not from my phone so I had to find another option.

My next attempt at serving the page over https to my phone used Tailscale's serve functionality whereby I could allow a machine on my local network (in this case, my Mac running Live Server) which is part of a "tailnet" to be accessible to other devices which are also on my tailnet over https. It was actually pretty simple to set this up - I signed up for Tailscale, installed the app and signed in on my laptop and phone and the tailscale serve command spat out a url that I could use to access my web page that was being served by my laptop over localhost. This worked in the sense that I could now access the page over https on my phone, but this is also the point where I found out the Web NFC API wouldn't work for my usecase. Not the end of the world, but I was a little disappointed. Oh well.

I still want to work on some sort of project, and I think I'll try to revive a little recipe maker/meal scheduler app that I've had on the backburner forever since I (really we, my partner and I) don't have a solid meal plan set up when we really could be benefiting from one. I'm excited to really get this one off the ground, for real this time, and finally get to practice some infrastructure as code type stuff.
